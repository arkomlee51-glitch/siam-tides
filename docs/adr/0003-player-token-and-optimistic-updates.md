# ADR-0003: player token ชั่วคราว และ optimistic update ฝั่ง client

วันที่: เฟส 3 · สถานะ: ใช้อยู่ (token จะถูกแทนในเฟส 4)

## บริบท

เฟส 3 ต้องการให้ server เป็นผู้ตัดสินคำสั่งให้ได้ก่อน แต่ระบบบัญชีผู้ใช้ (Supabase Auth) อยู่ในเฟส 4
ถ้ารอ auth ก่อน จะทดสอบเส้นทาง "client ส่งคำสั่ง → server รัน engine → push กลับ" ไม่ได้เลย
และฝั่ง client ก็ต้องตอบสนองไวเท่าตอนเล่นในเครื่อง ทั้งที่ต้องรอ network

## ตัดสินใจ

**1. player token ต่อที่นั่ง**

`POST /games` สุ่ม token 24 byte ให้ทุกที่นั่งมนุษย์ ส่งคืนครั้งเดียว server เก็บแต่ sha256
ทุก request เทียบ hash แบบ timing-safe แล้วได้ `factionId` ออกมา — จุดเชื่อมเดียวคือฟังก์ชัน
`GameService.authenticate` เฟส 4 จะเปลี่ยนข้างในเป็นตรวจ Supabase JWT โดย endpoint,
รูปแบบ error และ client ไม่ต้องแก้

ข้อจำกัดที่ยอมรับ: ใครถือ token ก็เล่นที่นั่งนั้นได้ ยังไม่มีการผูกกับตัวบุคคล เหมาะกับการพัฒนาเท่านั้น

**2. optimistic update เฉพาะคำสั่งที่ไม่มีการสุ่ม**

`viewFor` ซ่อน `rng` ไว้ (ไม่งั้น client ทำนายลูกเต๋าได้ = โกงได้) ดังนั้น client จะคำนวณผลของคำสั่ง
ที่มีการสุ่มให้ตรงกับ server ไม่ได้ เราจึงแยกเป็นสองกลุ่ม

- ไม่มีการสุ่ม (เดิน, ตั้งค่าย, สร้าง, เกณฑ์ทัพ, การทูตทั่วไป): apply ในเครื่องทันที แล้ว reconcile
  ด้วย view จาก server
- มีการสุ่ม (`attack`, `offerPeace`, `endTurn`): ตรวจว่าคำสั่งถูกกติกาในเครื่องเพื่อ feedback ทันที
  แต่ไม่แตะหน้าจอ รอผลจาก server (มีตัวบอกสถานะบน HUD)

ทั้งสองกลุ่มยัง validate ในเครื่องก่อนเสมอ คำสั่งที่ผิดกติกาจะไม่ถูกส่งออกไปเลย ลด round trip ที่ไร้ผล

**3. reconcile ด้วย version เดียวตัวเลขเดียว**

client เก็บ `version` ล่าสุดที่รู้ และทิ้งทุกเฟรมที่ version ไม่สูงกว่านั้น จึงไม่ต้องสน
ว่าผลจาก HTTP มาก่อนหรือหลัง update ทาง WebSocket และ modal (รายงานศึก/สรุปฤดู) ไม่ถูกเปิดซ้ำ
เมื่อเจอ 409 server แนบ view ล่าสุดมาด้วย client จึงกลับมาตรงกันได้ในหนึ่ง round trip

## ผลที่ตามมา

- เฟส 4 แก้แค่ `authenticate` และหน้าเข้าสู่ระบบ ไม่ต้องรื้อ route หรือ client
- ต้องมีตัวแสดงสถานะ "รอ server" บน UI ไม่งั้นคำสั่งที่มีการสุ่มจะรู้สึกเหมือนกดไม่ติด
- ถ้าเฟส 6 เพิ่มคำสั่งใหม่ที่มีการสุ่ม ต้องใส่ชื่อลงใน `RNG_ACTIONS` ของ `apps/web/src/store.ts`
  ไม่งั้นหน้าจอจะกระพริบเพราะ optimistic ไม่ตรงกับผลจริง
